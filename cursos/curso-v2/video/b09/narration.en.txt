Spotlight, the job platform for underrepresented people, has web and phone apps. A single screen in those apps often needs data from several services at once. If the app asks each service separately, it makes several trips over the phone's network and gets back more data than it will show. The team put a service built for its apps in front, what is called a backend for frontend. The app makes a single request with GraphQL, a way of asking for exactly the fields the screen will show. That service gathers what it needs from the others and returns it in one trip. The organizations and third parties that connect to Spotlight come in another way, with REST, the standard that has been around for decades and that almost anyone knows how to use. The cost is written down too. There is one more service to watch, and if it goes down the apps stop working, so it is deployed in several zones of the cloud.

The edge of a system is where whatever comes from outside gets in, from a person or from another system. That is where it is decided who gets in and through where. There are four families. The first is a shared door, a gateway, that receives the requests, checks who is making them and sends each one to the service it belongs to. It gains by solving access and security in one place. It pays with one more piece that everything goes through, and that cannot go down. The second is a door per type of client, like Spotlight's. It gains because each app gets just what it needs. It pays with more services to maintain, one per type of client. The third is letting files go straight to storage, without passing through the services. It gains because the services do not carry heavy files. It pays because controlling who uploads and who downloads each file has to be solved some other way. The fourth is deciding who starts the conversation, whether the system talks to the one outside or the one outside asks. Letting the outside ask gains because nobody has to find it online. It pays because changes only reach it when it asks.

Sysops Squad, the electronics company's support service, proposes another way of guarding the edge. After splitting the system into parts, the team asked itself where to handle authentication, authorization and the log of what happens. Repeating them in every service meant duplicating code. It proposes a gateway per part, because each part asks for different qualities. Billing, which stores credit cards, is isolated behind its own, because it is the highest security risk. Administration has another one, because it works with every permission and an intrusion there hits the whole business. The parts only talk to each other through those doors, and inside a part the services call each other directly. The rule the team writes is that the gateway holds no business logic. It checks access and security, and sends each request where it goes. That rule has a price. There are more services to build and maintain, and each gateway has to be spread over several copies so it is not the one point that, if it falls, leaves everyone outside.

Spotlight and Sysops Squad put up doors for different reasons. Spotlight built one for its apps, because its screens need data put together and few trips over the network. Sysops Squad proposes one per part, because each part has its own risk and its own load. In both cases, the door takes the shape of whoever arrives at it and of what has to be guarded behind it.

Files are a case of their own. On Spotlight people upload résumés, photos and the organizations' documents. Sending them through the document service meant a lot of work, and made it unreliable, because its memory would swell with the size of each file. So the app uploads them straight to a cloud provider's storage. The team wrote down the risk. Someone could upload a huge file or one in an invalid format, or download one that is not theirs. It covers this with signed addresses that last a short time. The system hands out an address that works for one file, with its size and its format, and that expires soon.

Wildlife Watcher is a system of cameras left out in nature to identify animals, running on batteries and without a stable internet connection. The cameras are configured from a platform. One option was for the camera to keep a door always open and for the platform to send it every change. That spends battery listening all the time, and if the connection drops halfway, the change never arrives. The other was for the camera to ask every so often whether there are changes for it, and if there is no internet, to ask on the next round. The second one won, and the cost was written down. A configuration no longer arrives the moment it is changed. When the one outside is unreliable, letting it be the one who asks avoids depending on finding it online.

At the edge, what has to be answered is who gets in, through where, and who controls that door. Your own apps and third parties ask for different doors, a heavy file is better off not going through the services, and a camera without network is better off asking for itself. And every door you add is one more piece that someone has to keep standing.
